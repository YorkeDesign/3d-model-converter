What happens during export

  • Transforms are baked — all rotation, position and scale changes are applied directly into the mesh vertex data. The exported file contains identity transforms on every node, ensuring consistent orientation across all viewers including Android Scene Viewer.
  • Geometry is optimised — duplicate vertices are merged and an index buffer is created, reducing file size by up to 80% compared to the raw parsed data.
  • Colours are preserved — per-vertex colours from the original USDZ are carried through to the export. They are quantised to 8-bit (visually lossless) for smaller files.
  • Normals are recomputed — smooth vertex normals are recalculated after optimisation to ensure correct lighting.
  • Original scale preserved — the preview viewport normalises the model to fit the viewer, but exports restore the original native scale and position from the source file.
  • Coordinate system — both USDZ and GLB use right-handed, Y-up coordinates. No axis conversion is needed.
  • USDZ file size note — exported USDZ files will be larger than the original because Three.js writes USDA (ASCII text) format, not binary USDC. Expect ~2–5× size increase. GLB exports use compact binary encoding and will be closer to the original size.
  • All processing is local — nothing is uploaded. Your files never leave your browser.
